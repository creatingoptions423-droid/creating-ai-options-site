01 / Testing capabilities

A closer look.

From individual behaviors to complete workflows, testing starts with what the system is expected to do.

QA / 01

Functional QA

Check intended behavior against requirements, including inputs, outputs, edge cases, and error handling.

QA / 02

Acceptance Testing

Translate acceptance criteria into clear checks, with results tied to the agreed scope.

QA / 03

Exploratory Testing

Investigate beyond the expected path. Follow questions, examine assumptions, and document unexpected behavior.

QA / 04

Workflow Validation

QA / 05

AI System QA

Evaluate instruction adherence, workflow consistency, tool interaction, state behavior, failure modes, boundary violations, and unexpected behavior.

Defect Verification

Document reproducible failures, retest fixes, and check related behavior for regressions.

Evidence Over Assumption

A behavior is not verified because it appears correct.

Reproducibility

Failures should include enough context to reproduce them.

Structured Classification

PASS, FAIL, BLOCKED, N/A, and observations remain distinct.

Human Judgment

Automation supports evaluation. It does not replace judgment where behavior is ambiguous.

TC-017 / EXAMPLEResult: FAIL

Cross-feature task navigation

EXPECTED
Referenced task identifier opens the corresponding task.
OBSERVED
Task identifier rendered as plain text instead of a navigable link.
EVIDENCE / EXAMPLE NOTE
Captured and reproduction path documented.
TC-018 / EXAMPLEResult: BLOCKED

Streaming interruption

EXPECTED
User can interrupt generation during a long response.
OBSERVED
No usable streaming state was exposed before completed output appeared.
EVIDENCE / EXAMPLE NOTE
Interruption could not be evaluated under the observed conditions. Retest requires an observable streaming state.
